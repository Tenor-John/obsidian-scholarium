# 文献元数据多来源接入设计（草案）

状态：**设计冻结前草案**。本文不包含任何 API Key、个人路径或机构凭据。

## 目标与非目标

目标是为 RSS 文献补齐可核验的 `abstract`、`authors`、`affiliations`、DOI、期刊与开放获取链接，并保存每个补齐字段的来源。研究智能可以发起请求和解释结果，但不得凭空生成这些书目字段。

本阶段不把任一来源当作全文下载授权，也不绕过出版社、机构或数据库的访问控制。

## 可信来源优先级

1. RSS 原始条目与出版社页面元标签：保留原值，不被自动覆盖。
2. Crossref：按 DOI 精确查找；适合 DOI、题名、期刊、作者、出版日期、许可和部分摘要。
3. OpenAlex：按 DOI 精确查找；补充摘要、作者机构、开放获取位置与关联标识符。
4. Semantic Scholar：按 DOI 精确查找；补充摘要、作者、引用/参考文献统计及可用 PDF 链接。
5. PubMed：仅生物医学文献；以 PMID/DOI 精确查找，补充结构化摘要、作者及 MeSH。
6. Scopus / ScienceDirect：仅在本地用户明确配置有效授权后请求；用于元数据、索引与授权范围内的链接。
7. Lens：仅在用户确认拥有有效 Lens Scholar API 许可和令牌后启用；保留 Lens 所要求的归属信息。

无 DOI 的题名检索必须进入“候选匹配”状态：显示题名、年份、期刊和匹配分数，由用户确认后才写入文章，不能自动覆盖。

## 字段合并与冲突

- 自动补全只填空字段，不覆盖 RSS/用户手工编辑的值。
- `abstractEdited: true` 永远禁止自动覆盖摘要。
- 每次写入记录 `metadataSources[]`：来源、实际写入字段、时间和用于查询的 DOI/标识符。
- 两个来源给出不同 DOI、标题或作者时，写入 `metadata_conflict`，不静默择一。
- 正文、AI 总结与 Research Radar 评分保留各自的来源与版本；元数据补全不会伪装成全文证据。

## 密钥与本地存储

凭据必须由用户在插件设置中显式输入或确认导入。导入外部本机配置时：

- 只读取用户明确选择的文件；不写回原文件，不在通知、日志、测试或 Git 中打印 Key。
- 保存前显示“将启用哪些来源”，但不回显完整密钥。
- Obsidian 插件数据默认是本机明文状态；设置页必须明确提示这一点，并提供清除单个来源凭据的操作。
- 所有 `data.json` 及其备份保持 Git 忽略。

## 请求调度

每篇文章先走无需 Key 的 DOI 精确补全（Crossref、OpenAlex），只有字段仍缺失时才请求启用的付费/限流来源。每个来源各自维护：并发上限、429/503 指数退避、超时、每日/每月配额计数和最近错误。

默认建议：Crossref/OpenAlex 并发 2；Semantic Scholar 1 RPS；PubMed 不超过其 API Key 许可速率；Elsevier 与 Lens 遵循账户合同和返回的限流头。全文下载与元数据补全使用不同队列，互不阻塞。

## 织研者 Action 契约

新增候选 Action：`literature.metadata.enrich`。

- 输入：文章 uid 或 RSS article id、允许来源列表。
- 输出：候选字段、来源、请求状态、冲突与未解决字段。
- 权限：读取外部元数据为 L1；写入文章元数据为 L2，必须显示字段级 diff 并取得用户确认。
- 禁止：将模型推断、搜索摘要或未确认的题名匹配写为正式书目事实。

## 分阶段交付

1. 已实现：按 DOI 的 Crossref + OpenAlex 补全、字段来源记录、阅读页手动补全、评分前自动补摘要。
2. 下一步：设置页凭据管理与导入确认、Semantic Scholar / PubMed 精确 DOI 适配器、队列和配额面板。
3. 随后：Elsevier/Scopus 适配器（含机构授权状态）；Lens 适配器（仅在访问许可确认后）。
4. 最后：将适配器注册给织研者 Action Registry，并为“无 DOI 的候选题名匹配”制作人工确认界面。
